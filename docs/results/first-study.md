- McNemar (mcnemar_exact): b=0 gained, c=0 lost, p=1
- Newcombe paired 95% CI on the difference: [-0.1617, 0.1617] (point +0.0000)
- Wilcoxon signed-rank on d_x: degenerate (n_nonzero=0, p=1) -- all 12 paired outcomes are identical, so the test is degenerate.

**Deviation from the reliability paper, stated plainly:** the paper's McNemar targets the per-task *consistently solved* indicator z_x = 1[c_x == n], which needs k > 1 attempts per task. These pilots have k=1, so we fall back to plain McNemar on per-task pass/fail. With zero discordant pairs the pilot pair is simply uninformative: 12 tasks cannot detect any realistic effect, and `required_runs` is undefined for an observed effect of exactly 0.

## 5. Cost and caveats: exactly where these numbers stop holding

1. **One domain.** tau-bench retail only. Nothing here transfers to airline, telecom, or code agents without its own study.
2. **One harness.** All trajectories come from the gate-calibrated collector (single agent scaffold, single user simulator model, single endpoint). Task categories are reduced to two tiers (irreversible / write); there is no deeper scenario nesting, so the hierarchical bootstrap has only ONE scenario level to resample.
3. **k is small.** The pilots have k=1 (the paper's consistency McNemar is NOT computable there -- plain per-task McNemar was used, with zero discordant pairs, i.e. no information). The collect run has k=2 and the policy runs k=4, so pass^k < pass@k gaps of +0.02 to +0.20 are real and computable, but each per-task z_x rests on 2-4 Bernoulli trials: 'consistent' on k=4 is weak evidence of reliability (exact one-sided 95% bound: a 4/4 task can still have up to ~53% chance of failing a fresh trial).
4. **Effect sizes are below the power floor.** The largest observed policy effect (~0.05 consistency proportion) would need ~700+ paired tasks for 80% power; the runs have 73-96 shared tasks. All null results should be read as 'underpowered', not 'equivalent'.
5. **Two comparability limits.** (a) The two pilot runs used the fit split with different task counts (19 vs 12); only the 12 shared tasks pair. (b) The five policy runs share 70-97 of their ~100 tasks; pairing is restricted to the intersection with 4 intact trials on both sides, so different pairs use different task sets.
6. **No repeated-attempt retries modeled.** Trials are trajectory-level rewards; abstention/error semantics from the collector did not arise (all rewards are 0.0/1.0), so `success=None` handling was never exercised on real data.
7. **Cost.** Zero for this study: everything above re-parses already-collected JSONLs offline. The underlying live collection was one-time spend on the Z.ai coding plan endpoint in the gate-calibrated project; this repository still makes no LLM calls.
